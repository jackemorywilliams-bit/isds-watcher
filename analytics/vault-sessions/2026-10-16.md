**What landed.** `STATE_OF_THE_ANSWER.md` is in the merge commit `5beba04` ("vault: archivist

this standing session exists to catch, and seven prior records describe it as a near-miss.

**The timeline, from the commit timestamps rather than from memory:**

| UTC | commit | what |
| --- | --- | --- |
| 15:25:09 | `815abfd` | my second revert pushed — the head my final path check read |

**The structural finding, and it is new.** Five prior records treat the pre-merge path check as the
thing standing between a routine session and an out-of-scope landing. **It cannot be, and this is a
property of the mechanism rather than of how carefully it is run.** `.github/workflows/reanchor.yml`
fires on `pull_request: [opened, synchronize, reopened]`, so every push to an open archivist branch
draws a fresh commit; the merge API reads the branch's head *at merge time*. Between the last path
check and the merge call there is a window the checking session cannot see into, and the bot writes
into it in under thirty seconds. **No number of re-checks closes a race; a later check only moves
the window.** The 2026-10-13 record came close to this — *"the last push is the one nobody
re-checks"* — but framed it as a discipline gap. It is not. It is unclosable from this side.

**What actually landed, measured.** The whole diff on `STATE_OF_THE_ANSWER.md` is **two lines** —
one removed, one added — and the only change is the machine-owned currency anchor, `a5326ed` to
`815abfd`. No substantive content was touched. **And `reanchor.yml` would have written the same
line to `main` itself seconds later regardless**, because since 2026-09-08 it also runs on
`push: branches: [main]` — recorded at `HANDOFF.md:264`. `scripts/check_currency.py` on the merged
`main` reports **5 notes, 9 currency claims, all current, 0 failed**.

**So I am not reverting it, and the reason is not convenience.** The landed line is the one line the
machinery owns, it is the value the machinery would have set unprompted, and reverting it would
both make `currency` red on `main` and constitute a second, hand-made edit to the same
out-of-scope file. Reverting would be a worse breach than the one it undid. **The harm here is
precisely zero bytes of content and one broken authorisation boundary, and the second of those is
the one that matters** — because a boundary that admits a trivial change under a race will admit a
non-trivial one under the same race, and nothing in the current mechanism distinguishes them.

### The procedural fix, found by using it — the merge can be made to refuse

**The amendment above says a pre-merge path check cannot close this race. That is true, and it is
not the end of the story: the merge itself can be made to refuse.** GitHub's merge endpoint takes a
`sha` parameter — the head the pull request must still be at for the merge to proceed. Pin it to
the exact commit the path check verified, and a bot push in the blind window produces **409 Head
branch was modified** instead of a silent out-of-scope landing.

**Demonstrated rather than proposed, on this record's own amendment pull request (#273).** The
merge was attempted pinned to `e178d2c`, a head whose path check had just returned two paths, both
in scope. It returned **409**: the bot had fired in the window, exactly as it did on #272. The
difference is that #272 merged the newer head and #273 did not. Reverted, re-checked, re-pinned,
and the second attempt merged at `7c459cb` — whose diff against its first parent is **five paths,
all inside `agents/` and `analytics/`.** A clean landing, on the same defect, in the same session,
twenty minutes after the dirty one.

**So the procedure for the next session, stated as steps rather than as a caution:**

1. Run the path check and note the head sha it verified.
2. Merge with that sha pinned, not with a bare merge call.
3. On a 409, revert the bot's out-of-scope path, push, and repeat from step 1. It terminates —
   this session's took two attempts.

**And a second flaw in the check itself, found the same way and pointing the other direction: the
three-dot form over-reports.** This session's instructions specify
`git diff --name-only origin/main...HEAD`. Three dots diffs from the **merge base**, so it lists
every path the branch touched since then and ignores what `main` did to the same path. Measured on
this record's third pull request (#274): after the bot's commit was reverted to main's exact
content, the three-dot check still listed `STATE_OF_THE_ANSWER.md` while `git diff --quiet
origin/main HEAD -- STATE_OF_THE_ANSWER.md` returned **identical** — the merge would change nothing
in it. A revert-and-recheck loop built on the three-dot form ran **five times without converging**,
because the condition it tests cannot be satisfied by reverting.

**The two-dot form, `git diff --name-only origin/main HEAD`, is what the merge will actually change
on `main`, and it is the one to check.** Both forms were run on #274 and only the three-dot one
reported a breach. So the check as specified errs in **both** directions: it cries wolf on a path
restored to main's content, and it cannot see a bot push that lands after it runs. The pair that is
right is the **two-dot** diff plus the **pinned sha**.

**This does not excuse the #272 landing.** That one was real and is established independently, by
the merge commit's own diff against its first parent (`git diff 5beba04^1 5beba04`), which is a
two-dot comparison and showed the anchor moving `a5326ed` to `815abfd`. The three-dot flaw explains
some wasted reverts; it does not explain away the landing.

**This does not retire escalation 11 and should not be read as retiring it.** It converts a silent
breach into a loud one, which is the difference between a defect that lands and a defect that
costs a retry. The out-of-scope commit is still generated on every push, the manual revert is still
required, and the remedy is still the one line above — a scope filter in `scripts/reanchor.py`, or
`STATE_OF_THE_ANSWER.md` added to this seat's record paths. **What changed is that the failure mode
is no longer invisible**, and that is worth having written down before the next session needs it.
