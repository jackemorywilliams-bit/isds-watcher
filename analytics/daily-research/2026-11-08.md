### 1.6 The second alarm was dead too, and this one has been dead for 33 days

This project has a dead-man's switch for exactly this failure: `heartbeat.yml` runs daily, reads
the newest `analytics/daily-research/*.md`, and emails an ALERT if it is more than 36 hours old —
its own comment says "a single missed day does not page; two missed days does."

It ran. Run **132**, `2026-11-08T01:01:36Z`. Its log, verbatim:

```
newest record: 2026-11-06.md (~0.0h old)
heartbeat OK — daily meeting is fresh.
```

The newest record was `2026-11-06.md`, committed `2026-11-06T22:31:27+00:00` — roughly **26.5
hours** before that line was printed. The watchdog read its age as **~0.0h**. The cause is at
`.github/workflows/heartbeat.yml:87-88`, which computes staleness from `os.path.getmtime`: git
stores no modification times, so `actions/checkout` stamps every file with the checkout instant
and `age_h` is approximately zero on every run. **`stale = age_h > 36` can never be true.** The
switch cannot fire at any staleness.

Demonstrated in my own container rather than argued: three records whose commit dates span
`2026-07-18`, `2026-09-07` and `2026-11-06` all carry the identical mtime `2026-11-07 15:09:13`,
this container's clone instant, and the step's own predicate evaluated here returns
`newest record: 2026-11-06.md (~20.2h old) / stale: False` — where 20.2h is the age of *the
clone*, not of the record.

**And this is prior art, 33 days old, which my own screen caught before I wrote it up as a
finding.** Insight ledger line **L242**, dated **2026-10-06**, thread
`INSTRUMENT-alarms-built-on-repository-file-state-are-dead-and-the-one-built-on-an-external-query-is-alive`,
already states it: "heartbeat.yml:76's daily-meeting staleness watchdog … keys on
os.path.getmtime, and git stores no mtimes, so actions/checkout resets every file on every run
and age_h is approximately zero ALWAYS … IT CANNOT FIRE AT ANY STALENESS." Its design lesson —
"build the next alarm as an external query, not as a read of repository file state" — was never
applied. `git log --since=2026-10-06 -- .github/workflows/heartbeat.yml` is **empty**: the file
is untouched, the defect is live, and **2026-11-07 is its first realized cost.**

So the honest statement of today's position is narrow and I keep it narrow. The two alarms that
should have caught a missed sitting both failed inside the same three-hour window, by two

false one about the wrong day. **Each mechanism is prior art; the compound instance is what is
