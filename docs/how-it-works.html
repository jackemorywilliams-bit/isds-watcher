The instrument

How the instrument works

The whole system on one chart, drawn directly from the repository it describes — every box and arrow cites the file that implements it.

Read it top to bottom. The first band is the nine public sources checked on every run. Beneath it the work divides into four columns: the machine — the automated pipeline that collects, de-duplicates, scores, and quality-gates each candidate development; what gets sent — the emails and site updates each stage produces; the AI-assisted review workflow — a multi-stage classification and review process in which separate model passes, each running under different instructions and each box naming the model it runs on, screen, analyse, challenge, and edit the week’s output, and in which a verification pass can block publication; and Emory’s verification column — the checks the operator carries out by hand. The moving dots trace work flowing through the system. On a desktop browser, hovering over any box shows its full description and the exact code behind it.

These passes are not independent researchers. They share source material, prompt lineage, model family, and this project’s framing assumptions, and can therefore share the same errors. Agreement between passes is not corroboration.

Claims here are machine-assisted and remain provisional unless an item is individually marked human-verified. One operator review cycle has been logged — 2026-07-18 — covering three claims from the research record: one verified against a primary source, one partially verified, one not reviewed. No digest entry and no sentence on this website has been checked by a human against its original source; every archived digest entry to date is machine-screened only. The operator has no access to paywalled sources, so claims resting on them cannot be operator-verified at all.
