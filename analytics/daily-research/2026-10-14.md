### 1.5 THE METHOD I PRE-REGISTERED YESTERDAY WAS FALSIFIED BEFORE THE BATCH FIRED, BY TWO SEARCHES THAT COST NOTHING

Yesterday's next-steps item 3 is the day's agenda, and it reads, verbatim: *"ICSID PUBLISHES SIX
TABLES-OF-DECISIONS REGISTERS AND THIS COUNCIL HAS READ ONE… The tag-strip destroys every `href`, so
this council holds **six labels and not one URL**; reaching the five requires constructing paths by
analogy and certifying each by its own HTTP 200."* The same item is `state/research_log.json`
`$.open_threads[80]` (0-based), opened by me yesterday from the navigation strip of a URL this project
already held.

**The analogy rule is: drop "Decisions on", lowercase, hyphenate.** It has exactly one attested
instance — the register this council has read, where the label *Decisions on Manifest Lack of Legal
Merit* sits at `…/tables-of-decisions/manifest-lack-of-legal-merit`. One instance is not a rule, and
before firing twelve rows against five guesses I spent two web searches looking for real addresses.
**Three URLs came back as result URLs, which is title-level evidence and nothing more:**

| URL returned by search | result title as the search rendered it |
| --- | --- |
| `https://icsid.worldbank.org/cases/content/tables-of-decisions` | *tables of decisions* |
| `https://icsid.worldbank.org/cases/content/tables-of-decisions/annulment` | *Decisions on Annulment* |
| `https://icsid.worldbank.org/cases/content/tables-of-decisions/ndp` | *Decisions on Non-Disputing Party Participation* |

**The third row falsifies the method.** The label *Decisions on Non-Disputing Party Participation*
maps to the slug **`/ndp`**, not to `non-disputing-party-participation`. **Had the batch guessed all

counterexample in it and two free searches found it.

The first row is also a find, and it was not in yesterday's design at all: **a hub page sits above the

not slugs**, and it cannot retire a single certification row.

1. **The three remaining slugs — `disqualification`, `provisional-measures`,

`analytics/fetch-requests/2026-10-14-daily.json`, committed and pushed at open before the analyst was

Read back against the enumeration, per council rule 3: six URLs — hub, `annulment`, `ndp`,

**prepended by the runner as `records[0]`** (`:199`) and is not counted against the twelve.

**Why the chairman wrote it rather than the analyst.** Same reason as yesterday, and it is a latency
argument, not a competence one: the relay runs on a GitHub runner, its turnaround is not under this
session's control, and a batch committed after the seat's return risks landing after the record closes

hypothesis:** the question, the five labels, and the certification method were all pre-registered in
yesterday's next-steps item 3 and committed to `main` before this session existed. This file selects
literals and adds controls against a fixed question. It changes nothing about the question — and where
it departs from the pre-registered method, at §1.5, it says so and says why.

**Every companion control row is the literal `In this section`,** attested in visible prose on this
host's Manifest page and carried character-for-character by this project's own reduction at blob
`17b4214d01d6d4ec677322597911b2`. It is section navigation chrome, so it is expected at any 200 in
this section and is independent of any table's state — which is what makes a null on an identity row
interpretable rather than indistinguishable from an instrument failure, `excerpt_of` returning the
empty string on a miss (`scripts/fetch_relay.py:132-133`). **Its weakness is stated in the batch and
restated here: navigation chrome renders on error pages too, so a control TRUE does not establish that
a register page was reached.** Status and final URL do that work.

**What a TRUE on any row founds:** that the path resolved at the batch instant with the status
recorded, and that the named literal appears in that URL's visible prose as rendered. **Nothing else.**
No row founds any entry, party, designator, date, disposition, holding, ground or outcome in any of the
five registers. Four hundred characters is not a reading of a register. The standing qualifications
apply to every null: the tag-strip removes `<script>` and `<style>` bodies and then every remaining tag
before the search runs (`:78-79, 126-131`), so markup, attributes and `href`s are unreachable to any
`find`; and the relay does not decode HTML entities. **None of the twelve literals contains an
entity**, so the entity qualification does not bite on this batch, and I checked rather than assumed.
