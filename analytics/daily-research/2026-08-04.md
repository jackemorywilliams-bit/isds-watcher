**Four properties of the relay instrument that I had to establish from `scripts/fetch_relay.py` before reading any row, and which the record should carry:**

1. **`find` is case-insensitive.** `excerpt_of()` does `body.lower().find(find.lower())`. So the 08-03 row that requested lowercase `relationship between forums` and matched a page rendering `Relationship between forums` is not an anomaly, and a `find_matched: false` cannot be explained away by capitalisation.
2. **`find` runs against tag-stripped text, not raw HTML.** `_TAG_RE` removes `<script>`/`<style>` blocks entire; `_ANY_TAG_RE = re.compile(r"<[^>]+>")` removes every tag *including its attributes*. **Consequence: a string present only inside an `href` or other attribute is invisible to the relay.** This directly qualifies the A/81/17 null below, and it is a material difference from the 2026-08-01 officer's null, which was verified against raw HTML.
3. **`find_matched` is `bool(excerpt)`, not an independent test.** A row whose `find` string is one the target page would echo back from the request itself cannot distinguish "present in the document" from "echoed from the URL." That defect is realised in today's `undocs.org` row (Task 3(b)).
4. **The control row's `find_matched: false` is an artefact of an empty `find` string**, not a control failure. `control_ok` is `outcome == "ok"`, and it is true. No one should later read that `false` as a degraded control.

**Method note for the self-training file (this is the day's transferable lesson).** The 2026-07-26 lesson was *author-name+title beats keyword search*. Today's is the relay analogue: **never choose as `find` a string the target page can generate from your own request.** The productive form is the one both UNCTAD rows used — request a *neighbouring structural label* (`"ISDS forum options"`, `"A/80/17"`) and read the answer out of the window around it. The label you ask for is the anchor; the value you want is what sits next to it. Two anchors on the same page, chosen on opposite sides of the target, bracket a cell value and prove the page's element ordering at the same time. ### 2.2 The reconciliation

**Ruling I propose: the two-category usage at `STATE:64`/`:84` governs. It is the later formulation, it is the sourced one, and it is the only one the record ever defended.** The three-term list at `2026-07-08.md:64` is a **superseded formulation**, and its middle term's parenthetical gloss is a **drafting error** — it restates the FITR definition under the "no-U-turn" label, one day before the record acquired the sourced definition that places no-U-turn in the withdrawal-cure position. Confidence: **HIGH** — this is a documentary finding about the record's own texts, and all five supports are on file and quoted.

**But the 07-08 note was groping at something real, and the two-category scheme does not contain it.** That is the part of the reconciliation that matters for Task 1. Three structures are genuinely distinguishable:

- **(A)** irrevocable on domestic filing — FITR;
- **(B)** curable by withdrawal, but only before a domestic merits judgment — no-U-turn, per the record's sourced definition at `2026-07-09.md:75`;
