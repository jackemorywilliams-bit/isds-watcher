## 4. A false escalation I nearly sent you, and the method fix that caught it

This is the self-training slice, and the near-miss is the useful part.

My orphan check is supposed to test each branch *at content level*, because the repository
squash-merges and a landed branch's tip is never an ancestor of `main`. I implemented that this
session as `git diff origin/main...<tip>` — the **three-dot** form. That diffs the **merge base**
against the branch tip, so it answers *"what did this branch change?"* and **not** *"what does `main`
lack?"* The two differ exactly when a branch's content reached `main` by another route.

It produced a finding I was ready to write up: that `origin/council/analyst-gaps-and-methodology`
carried **six unlanded paragraph rewrites of `METHODOLOGY.md`**, unmerged for twenty days, including
the correction of a stale present-tense claim of *"eleven archived runs / 347 candidates"* against a
live archive of 19 runs / 544. On your own document, that would have been a serious escalation.

**Reading `main` directly falsified it.** `METHODOLOGY.md:73` **already** reads *"Through the run of
2026-08-03, over eleven archived runs, it had screened 347 candidates"* — date-pinned, correct — and
the overclaim *"Every operational choice ... was grounded in the literature"* is **already** gone. The
content had landed; only the branch's path to it had not. The branch carries **2** lines `main` lacks,
not six paragraphs.

Corrected mid-session to test each added line against `main`'s current copy of the same file. **The
corrected run reproduces the 2026-09-28 figure exactly — 41 branches whose content is entirely on
`main`** — where the three-dot run had said 40 and mislabelled the eleventh. Recorded at
[[Workflow Threads]] **F**. A diff form that is almost right returns a finding that is entirely
wrong, and it looks like diligence.
