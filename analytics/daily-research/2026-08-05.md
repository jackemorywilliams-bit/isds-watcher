## TASK 2 — Mapper attribution and vintage, UNCTAD treaty 978

### 2.1 (a) What today's `Mapped by` row establishes — and the chairman's reading, tested against the code

**The chairman is right, and the code confirms it exactly.** I tested the reading three ways.

*The code.* `excerpt_of` at `scripts/fetch_relay.py:130-135`:

```
    if find:
        idx = body.lower().find(find.lower())
        if idx == -1:
            return ""
        start = max(0, idx - EXCERPT_CHARS // 4)
        return body[start:start + EXCERPT_CHARS]
```

`str.find` returns the **lowest** index of the substring. So the window is centred on the first case-insensitive occurrence in the tag-stripped, whitespace-collapsed body, with `EXCERPT_CHARS // 4` = 100 characters of left context and 300 of right (`EXCERPT_CHARS = 400`, `:42`).

Individual treaties are "` — and `excerpt[100:]` begins `"mapped by law students…"`. Because `start = idx − 100`, the match therefore sits at excerpt offset exactly 100. **The matched occurrence of "Mapped by" is the one inside "…Individual treaties are mapped by law students from participating universities…".** That is arithmetic on the returned reduction, not inference.

### 3.2 The relay cannot bootstrap its way to a document URL — and this is the decisive point

Even holding the UNCTAD landing page, **the relay can never learn the treaty-text link target from it.** `_ANY_TAG_RE = re.compile(r"<[^>]+>")` (`:79`) removes every tag *including its attributes* before any matching or excerpting happens (`:126-128`). An `href` is an attribute. **The relay is therefore structurally incapable of reporting a hyperlink target from any page it fetches.** It can only ever reach URLs a human already put in the record. The allowlist is a policy expression of that; tag-stripping makes it a property of the instrument.

### 3.3 What the reduction would look like if the text is a PDF — and the trap that must be pre-empted

`excerpt_of` begins (`:124`):

```
    if "html" not in content_type and "text" not in content_type:
        return ""
```

A PDF returns `content_type: "application/pdf"`, which contains neither substring, so **`excerpt` is `""`**. And because `find_matched` is `bool(find) and bool(excerpt_of(...))` (`:181-182` — the B6 correction, applied), **`find_matched` is `false`**.

So the reduction of a treaty-text PDF would be: `outcome: "ok"`, `status: 200`, `final_url`, `content_type: "application/pdf"`, `bytes`, `sha256`, `excerpt: ""`, `find_matched: false`. **That is existence plus a fingerprint. It is not one character of text.**

**The trap, stated before anyone ever fires such a row:** on a PDF row, `find_matched: false` is **guaranteed by the content-type gate alone** and carries **zero** information about whether the string is in the document. A future session reading a PDF row's `find_matched: false` as "the phrase is not in the treaty" would be committing a false negative of exactly the class the `undocs.org` row nearly produced. This is the PDF analogue of the echo defect and it should enter the record under instrument/method now, not after it bites.

### 3.4 And even for HTML, the channel cannot deliver a provision

`EXCERPT_CHARS = 400` (`:42`), of which 100 are left context. The relay's own docstring states the design: *"What travels is the REDUCTION, never the document (council standing rule, 2026-08-03)… No third-party body is written to any file, branch, artifact, or log. The repository is public; a commit is publication."* (`:10-13`). Reading a provision through it would require a chain of anchored rows, each anchored on a string you must already know is in the document — and you cannot know it without having read the document. `MAX_URLS = 12` (`:76`) caps a chained walk at roughly 12 × 300 ≈ 3,600 newly-seen characters per batch under ideal conditions, and there are no ideal conditions, because `find` is literal-only and the reduction reports no offset.

### 3.5 Disposition

**The residual `china-switzerland-bit-2009-forum-provision-text` is not relay-work, and no relay budget should be spent on it.** The relay cannot deliver this instrument's text — not because of a defect, but because delivering documents is the one thing it was deliberately built not to do. A reasoned "no" is the whole of my answer to Task 3 and I do not dress it up as anything else.

**Two things the relay *could* honestly do, if and only if the operator supplies a locator** (chairman's call, not mine; I propose no spend):

1. If Emory or anyone puts a treaty-text URL **on an allowlisted host** into the record, one relay row would confirm that the named file exists at the named locator, is reachable under the project's own identifying User-Agent with robots.txt honoured, and record its byte length and sha256. That is a **provenance fixture** — precisely the preserved-snapshot discipline the July 31 lesson asks for and that the China–France ledger row was faulted for lacking. It is not a reading of the treaty and must never be written as one.
2. Nothing else.

**Where the residual should actually live.** It is either (a) an operator manual retrieval with a preserved `source_snapshot` — the same shape as downgraded escalation 2, and the two could be executed in one pass; or (b) a search-track item against an accessible secondary that reproduces the forum provision verbatim; or (c) it stays open, honestly, as an unread instrument.
