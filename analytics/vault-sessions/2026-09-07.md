## 1. The finding — `reanchor.yml` has been a no-op for nine days, and it loses by seconds

`.github/workflows/reanchor.yml` exists to move the tracked notes' currency anchors to the PR tip
so a merge does not land on `main` with stale anchors and a red `currency` guard. It runs on every
PR. **It has not worked since 2026-08-29.**

Of every `chore(currency): re-anchor tracked notes to HEAD [skip ci]` commit
`github-actions[bot]` has ever authored: **2 landed on `main`, 14 never did.** Both survivors are
dated 2026-08-29 — `08380af` and `e8b0f71`.

**The mechanism is a race decided by seconds**, and it is the same in every case I measured. The
seat squash-merges its own pull request; the bot then pushes the re-anchor to a branch that no
longer has anywhere to go:

| Branch | Merge to `main` | Bot re-anchor | Gap |
| --- | --- | --- | --- |
| `council/2026-09-07` | `6a8a126` 12:17:18Z | `767cccd` 12:17:29Z | **+11 s, too late** |
| `council/2026-09-07-addendum` | `4bbe5cb` 12:20:13Z | `bb694b5` 12:20:21Z | **+8 s, too late** |
| `council/2026-09-06-addendum` | `101a479` 12:11:34Z | `cd59bce` 12:11:42Z | **+8 s, too late** |
| `vault/archivist-2026-09-04-ci` | `4983ffd` 15:26:52Z | `4f8c376` 15:27:08Z | **+16 s, too late** |

Four for four. Each of those branches shows up in the orphan sweep carrying an anchor-only diff
against `main` — one line per tracked note, written by the bot, stranded by construction.

**I want to be exact about what is new here, because the failure mode itself is not.** The
workflow's own author wrote it into the header when the workflow was built
(`.github/workflows/reanchor.yml:9-17`):

> *"Honest limit, stated so nobody trusts more than it delivers: the daily council squash-merges
> its OWN pull request via `gh`, and does not wait for checks. This workflow commits the re-anchor
> to the PR head, but if the session merges before it lands, the merge is still stale."*

That comment names two covers. One is the council's own close-out `reanchor.py` call. The other is
making `currency` a **required check** on `main` — which would block the squash until the bot's
commit lands — and the comment records that it was *"Recommended in the PR that adds this."*
**It was never applied.** What is new is the measurement: the predicted limit is not an edge case,
it is the normal path, 14 times out of 16.

**And the first cover does not reach the notes that need it.** The council does run
`scripts/reanchor.py` at close-out, but commits only `STATE_OF_THE_ANSWER.md` — `agents/` is
outside its merge scope, stated in today's record and visible as `2c3c44c`, `70a97da`, `7a298a1`.
So with the bot losing the race, **the four `agents/` anchors have no automatic mover at all.**
Every commit that has ever moved them on `main` is an archivist commit — `516f89c`, `ed68d4e`,
`cdeff0f`, `aa7c572` — and this seat runs every three days.

> **NEEDS YOU — this is one repository setting, and it was the recommendation attached to the
> workflow when it was built.** Make `currency` a required check on `main`. The squash then cannot
> complete until the bot's re-anchor has landed, and the race disappears rather than being won.
> The alternative, if you would rather not gate merges: have each seat run `scripts/reanchor.py`
> *before* opening the PR, which is a systems-designer change to the protocols. **Either one also
> closes D11** — a pre-merge anchor leaves the bot nothing to push, which is what makes every
> archivist PR unmergeable by the archivist today. Tracked as **D16**.

**This supersedes a reading I recorded on 2026-09-04.** That session described the council
re-anchoring only `STATE_OF_THE_ANSWER.md` as "one seat's voluntary restraint." It is not
restraint; it is a scope rule, and the measurement above is its consequence. **D10** is corrected
